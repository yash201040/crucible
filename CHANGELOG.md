# crucible changelog

Every change to the framework, newest first. Automatic entries come from `crucible-evolve` (run = after one run, periodic = weekly/monthly review) and cite the run and evidence they rest on.

## 2026-11-19 (manual; asked for by the user): v5.3, fewer model calls per agent (Code Mode)

Asked for by the user: crucible should run with Claude Code's experimental Code Mode whenever it is used within Claude, and use the corresponding Codex feature where there is one. Evidence for the cost it addresses: in the first v5.0 run an agent needed 68.9 model calls on average (20,800 in all) and the run re-read 4.1 billion cached tokens, 13.6 million per agent; every model call re-reads the context so far.

What was found about Code Mode (Claude Code 2.1.325, its documentation and one headless call): it is switched on when a session starts (`CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`, confirmed once by the user), only in an interactive terminal session. A headless call with the variable set prints "Code Mode (experimental) isn't available: for now it only works in the interactive terminal" and starts with the ordinary tools. Both large runs so far were started from an app built on the Agent SDK, where it cannot be on. Whether agents started by a workflow get the script tool is not documented.

- Engine: one more rule for every agent: work in few, large steps; with a tool that runs a script which can call the other tools, do related reads, searches and commands in one script and return only the lines needed; without one, send independent tool calls together and filter output before reading it. It never replaces a required check. Cost: about 95 tokens per agent prompt. The rule names no host. `codeMode` (what the front desk saw) is recorded in the result and changes no prompt.
- Front desk (Claude Code): it has Code Mode if it has the REPL tool. On: it passes `codeMode: true`. Off: one line to the user on how to get it (start the session with `bin/crucible-claude`; in an app, that it cannot be on there), repeated at approval for a plan of 30 agents or more. The run is not held back.
- `bin/crucible-claude` starts Claude Code with the variable set.
- Codex: agents ask for `features.code_mode` (under development in Codex); an agent that fails with it is run once more without it; `"code_mode": false` in `~/.crucible/providers.json` turns it off. Headless `claude -p` agents are never asked for Code Mode.
- Efficiency log: `steps` (model calls per agent, mean and median; tool calls; script calls; agents that ran scripts; cached tokens re-read per agent). Two new numbers for expectations, and one expectation: model calls per agent at most 55 (from 68.9; a guess of a fifth, to be corrected by the first measured run).

Probes (headless Sonnet, so without Code Mode; engine before the v5.2 and v5.3 prompt changes against after): all 8 cases right on both versions, no regression. On the five short cases run a second time with counts: 32 model calls before, 30 after; 633K tokens read before, 552K after; one run per case, so this is within noise. The probes are too small to show a saving: they already take five or six calls. Probe runs now record model calls and tokens, so two engine versions can be compared on cost.

Not verified: no run has been made from a Code Mode session, so neither the saving nor whether workflow agents get the script tool is known. Codex's code mode has not been run against the real CLI.

## 2026-11-19 (manual; asked for by the user): v5.2, the self-review reads the runs, a runner for other hosts, no data tool in the framework

Asked for by the user after the analysis of the first v5.0 run was done by hand: the self-review should do that reading itself, on every run of the latest version or on the runs the user names; the skill should be shareable on its own, usable from Codex, and without the user's own data tool built in.

Self-review
- `review-pack` chooses the runs: those named after `--review` (a run folder, a file in it, a piece of its name), else every run made on the current engine version, else (when that version has not run) the runs since the last review. Runs on older versions stay in the pack as background. A name that fits no run or several is an error, not a guess.
- Per run it writes a digest recomputed from the records, without touching the run folder: time and budget, attempts kept and discarded, findings by kind, parts whose rounds did not shrink the open findings, acceptance clauses over an open set, issues and unanswered requests between parts, context sizes, what never started. On the first v5.0 run it reproduces the figures of the hand analysis (302 agents, 161 agent-hours, 130 attempt agents of which 18 kept, 0.52 of agent time discarded, use over estimate 1.63, 53 of 100 solvers over 300K) and finds the open-set clauses in both parts that ran ten rounds.
- It copies what the user typed in the run's conversation after the result arrived, and whatever the user says when asking for the review. Both are passed to agents as data, never as instructions.
- `crucible-evolve` has an Audit phase before it selects changes: per run, one reader each for the work, the answer and what happened afterwards (one reader for a run under 20 agents; at most six runs in full). They answer the eight questions of `references/run-audit.md` with figures and name leads with the stage that could have prevented each. The selector weighs leads and proposals; a verifier of an audit-based finding recomputes the auditor's figures.
- Every finding states one number of the digest it should move, its value now and the value wanted. `evolve-save` records it for the applied ones in `references/expectations.json`; each later review measures the open ones on runs of that version or later and sets them met, not met or dropped. The file starts with seven entries for the v5.1 changes, with the first v5.0 run as the baseline.
- After a review that changed the engine, `probe-check` runs the probe cases whose rendered prompt or reply format changed, on the engine before and after. A case that was right and is wrong, twice, is reverted: only the commits that changed that case's prompt, else every commit of the review; by revert commits only. The applier adds a probe case for a prompt change where a right answer can be known, and raises the engine version by a patch step so later reviews can tell runs apart.
- A review no longer needs its own crucible run on the history (`--deep` asks for it).

Other hosts
- `runner/crucible-runner.mjs` runs the same workflow scripts outside Claude Code: agent, parallel, pipeline, phase and log, a cap on agents alive at once, a journal that the save step reads as it reads a Workflow run, and replay of finished agents on a relaunch. `--detach`, `--status`, `--stop`.
- `scripts/crucible_agent.py`: the Codex route sends the reply format as a strict schema (closed objects, optional fields as null) and reads the reply back into the original one; a refused schema is tried once more in the prompt. A role name from the routing table is never passed to Codex as a model: it is mapped in `~/.crucible/providers.json`, else the CLI's default is used. A model is now optional for the Claude route too.
- `hosts/codex/SKILL.md` is the front desk for Codex; `crucible_run.py install --host codex` installs it.

No data tool in the framework
- The engine's rule for external data no longer names a tool. `dataNote`, `dataRules`, `dataTool`, `dataBudget` replace the earlier tool-specific args; the paid-call ledger and fetch cache are read only where `~/.crucible/local/local.json` names them. An installation's own flags and rules go in `~/.crucible/local/front-desk.md`, which the front desk is shown at the start of a run.

Checks: `node tests/run.mjs` (the engine suite, plus `tests/test_review.py` and `tests/test_runner.py`); each new rule was confirmed by breaking it in a copy. One small real run through the runner and the Codex route, with a stand-in `codex` command that forwards to `claude -p`: three agents, the right answer, saved by the normal save step.

Not verified: no review has yet run on the new flow with real agents. The Codex route has not been run against the real Codex CLI. v5.1's changes still await their first large run.

## 2026-11-19 (manual; asked for by the user): v5.1, staged attempts, budget by importance, ownership, closed acceptance lists, complete handoff
Evidence: the first real v5.0 run, a product build (run 20261115-151007, 302 agents, 31 h, 161 agent-hours, every agent on Opus by the user's instruction). Measured from its journal, transcripts and result with the efficiency log, plus three independent reads of its findings, its plan against the later hand assembly, and its final merge:
- v5.0's scheduling worked: 5.2 agents alive on average at a limit of 6 (2.55 before), so wall time was total agent time over 6.
- 130 of 302 agents and 92 of 161 agent-hours went to the parallel attempts; 18 of those agents worked on an attempt that was kept. The repair attempt alone survived in 6 of the 12 parts that got attempts; in the 6 where it failed, the first fresh start rescued 2 and nothing rescued the other 4.
- Estimate 185 agents, ceiling 301, used 302: the run wrapped up before its last two parts, the assembly and the end-to-end proof, the two the user's success definition rested on. The assembly was then done by hand: 131 commits, 10 stand-ins to replace, 6 mismatches between parts, 18 fixes from the first live run.
- Of 142 blocking findings, 85 were product defects, 32 test strength against mutants the attacker wrote, 14 bookkeeping, 7 causes outside the part, 4 empty hand-backs. Two parts had contract clauses over an open set ("every wrong implementation the verifier writes must make the suite raise"): 26 of their 32 blockers were new instances of that class, over ten rounds each. The part whose contract listed a closed set passed in round 1.
- 0 of 18 parts ended verified: all 12 repair checks listed leftovers and any leftover meant "flawed".
- Parts that ran at the same time never saw each other; 249 boundary notes reached only the synthesizer; one missing interface field was reported 11 times and worked around 11 ways. No part owned the overall interface or the data handed between steps, and the user's main quality concern had no part.
- Solver contexts: median peak 320K tokens, maximum 678K, no compaction; 4.1 billion cached tokens re-read.
- The final answer was honest about status; of 20 traced statements 15 were accurate, 3 wrong (one figure credited to an attempt that was not the kept version), and the handoff carried 17 of 33 open blockers and 18 of 47 leftover flaws.

Changes (engine v5.1 unless a file is named):
- Staged attempts (runPair): after the two serial rounds and the referee, the repair attempt runs alone; the other strategies start side by side only if it fails, one round at a time, and stop when one has survived (a barrier per round, so a resume replays the same calls). A referee ruling `repairable: false` skips the repair. Round numbers keep each strategy's slot, so labels and round folders are unchanged. `fanout` gains `staged`, `planned` and the outcome `stopped`.
- Budget by importance (gate, reserveFor, markCritical): the planner marks the scopes the result is unusable without as critical (their prerequisites become critical too). Every spend goes through one gate: attempts and repairs leave room for every scope not yet started; the base work of a scope that is not critical leaves room for the critical ones still waiting; critical scopes are queued first and get every attempt, the others one further attempt. A plan that marks nothing behaves as before.
- Estimate: it counts the expected retries (share of scopes still open after two rounds: 0.6 for moderate and hard, measured 12 of 18) and the repair after a review; the headroom above it is smaller (quick 1.15, standard 1.2, deep 1.25, max 1.5; was 1.3 to 2). The token calibration is 70K output tokens per agent (40.5M over 582 agents on the two large runs; was 45K); the weekly share per agent is unchanged because the weekly allowance is not measured.
- Ownership (SCOPE.owns, PLAN.success_items, DECOMPOSE_RULES 11 to 13, planLint, plan critic): every item of the success definition has one owning scope; what two scopes touch has one owner; a build gets an early skeleton and an end-to-end proof that does not wait for optional scopes; one component per scope; research that should shape a scope is its prerequisite. Mechanical checks (no owner, two owners, more than half critical, a critical scope that waits for most of the plan) go to the plan critic and into the plan result (`plan.lint`). Each brief says what the scope owns and which success items it is held to, and carries a plan map of the other scopes and their ownership.
- Request board: scopes that run together talk through files in `<runDir>/board/` (prompts stay fixed, so resume still replays): incoming requests are settled with a reply file, outgoing ones replace silent workarounds. The synthesizer and the completeness critic read the folder; the answer's `success_items` reports each item against its owner.
- The bar: the contract writer must use closed thresholds and name what the scope does not control (`open_classes`, `outside_control`); a clause over an open set is detected in code (OPEN_SET) and read as its listed instances. Every attacker finding carries a class; `test_strength` beyond the listed cases and `out_of_part` never block, in code, and an `out_of_part` finding is recorded as a split problem for its owner. The referee rules such findings caveats.
- Repair check: `remaining_material` separates leftovers that change what the user should conclude from the rest; only those keep a result from verified (a check without the split is read the strict way).
- Versions: every avenue in the atlas says which attempt produced it and whether that attempt is the kept version; the synthesizer is told the kept version per scope and to compare both sides wherever two scopes meet.
- A solver that hands back nothing (no claim, no evidence) is not attacked; the round is recorded as empty.
- Handoff (scripts/crucible_run.py open_items_appendix): below the synthesizer's text, save appends a complete list generated from the result: success items by owner, every open blocking finding with its check, every flaw left after a repair, every issue between scopes, every unanswered request, every scope that never started. The result carries these in full (`open`, `caveats`, `repairLeft`, `kept`, `critical`).
- Efficiency log (build_efficiency): `attempts` (agents and seconds on attempts, and on the kept one; how often the repair alone was enough; survival per strategy), `budget` (estimate against use, scopes that never started, critical ones named), `finals`, `context` (largest solver context, solvers above 300K, cached tokens re-read). On the run above it reproduces the figures of this entry.
- Solver prompt: work within one session's reach, and report a scope that is several components' worth of work as mis-scoped instead of half-finishing all of it.
- PROTECTED.md 7 and 14 extended, 17 added (ownership and order). tests/run.mjs: the two expectations that encoded "all attempts at once" were changed on the user's instruction; 39 tests added (238 in all); each new rule's test fails when the rule is removed (10 mutation checks). tests/audit: the handoff comparison accepts the generated list after the returned text.
- Prompt probes (calibration/calibrate_rules.py, calibration/render_prompt.mjs; results in calibration/results/20261119-rules.json): 28 small live agents, each on the prompt the engine itself renders. Attacker, 4 cases on Sonnet high and Opus high: correct work with one more surviving mutant accepted (4 of 4, also with the contract clause "every mutant the checker writes must be killed"), the extra mutant filed as test_strength; a real defect that no listed test catches found and blocking (4 of 4, class behaviour); a listed check that fails because another scope has not delivered filed as out_of_part with the owner named and not blocking (2 of 2). The v5.0 prompt gave the same accept and block decisions on these small cases, so the probes do not reproduce the ten-round loop; what they show is that the class is filled in correctly and no real defect is lost. The loop fix itself rests on the code rule. Two things the probes changed: `class` became a required field (left optional, Sonnet omitted it in 3 of 4 runs), and the first reference implementation of the probe had a real defect that both models found (the probe was corrected). Contract writer, 2 scopes, one of which invites "cannot be evaded": 6 of 6 contracts under the new prompt had no clause over an open set and named their sampled classes and what the scope does not control, in 123 to 616 s; the 2 runs on the v5.0 prompt did not return a contract within 900 s. Referee: the extra mutant ruled a caveat and the real defect upheld (3 of 3, v5.0 included). Planner on a small build: 10 scopes, 10 success items each with a valid owner, every scope with an owns list, 5 critical (the skeleton, the proof, the hold-out data and the two scopes carrying the user's main point), the proof depending on 4 scopes instead of all 9. The plan critic, on that plan, raised 18 issues, among them that the user's main point had no single owner, that the proof depended on none of the parts it must run, and that the part carrying the user's safety rule was not marked critical.
- The open-set pattern at first flagged "every mutant m01-m20", a closed list, in one of those contracts; it now leaves a named or listed set alone (tested on 5 open and 6 closed wordings).
- Not verified on a real run: the user asked for no large run. Everything above ran in the mock harness, on the saved records of the run above, and on the small live probes.
- Not done: no agent amends a finished scope when requests for it arrive later (the assembling scope settles them); a scope's solver is not stopped at a context size (the runtime gives a script no view of it; the planner sizes scopes and the efficiency log reports the peak); the reviewers (debunk panel) still see only the kept version.

## 2026-11-15 (manual; decisions delegated by the user): v5.0, model routing, bounded rounds with parallel attempts, other providers, efficiency log
Asked for by the user on 2026-11-15 after watching the third audit session: a few parts looped solver-attacker for many rounds, the run sat at one or two live agents, every agent ran on the session's heaviest model, and the flow was tied to Claude. Evidence gathered that day: research notes in the design folder (agent-orchestration/research/20261115/: loop convergence, model tiers, harnesses, self-improvement, the Dream-RSI paper, three repositories), calibration runs (calibration/results/), and the session's own logs measured with the new efficiency log: 36 h of active time at 2.55 live agents on average (peak 6), one or two alive for 67% of it, 38% of output tokens spent after first rounds, one part 8 rounds deep (14.8 h of serial agent time).
- Rounds (engine, runPair/attempt): a part gets at most two serial solver-attacker rounds (was 2-10). Still open: if the solver disputes the findings or each attack raised new ones, one referee on the strongest route runs each finding's check and rules (a rejection counts only with an executed check); then K fresh attempts run side by side (easy 2, moderate 3, hard 3, frontier 4; scaled by depth), each with its own strategy (repair, fresh start, check first, second fresh start, simplest correct), one difficulty up, each with its own attacker. Code picks the winner: an attempt that survived, else one ranked strictly above the earlier best, else the earlier best stays. This replaces escalation (one more serial pair at the next difficulty) and the stalled/saturated patience rule. Sources: parallel candidates after a failed round beat more repair rounds (arXiv 2604.16529, 2607.02807, 2609.14858); later rounds degrade unless every version is kept (EMNLP 2026); stall threshold of two (Magentic-One).
- Repair and re-review prompts: round two repairs the previous submission with the smallest change instead of pushing a new line of work; a re-review checks the earlier findings first, then regressions, then the rest, and the bar is the contract, not a stricter one. Objections carry an origin (new / previous / regression) for the log.
- Scheduling (runLayer): a part starts when its own prerequisites are reviewed; dependency layers are no longer barriers. Hardest parts are queued first. Race plans keep their waves.
- Routing (routing.json, engine ROUTING_DEFAULT, `stage --profile`): each role's model and effort come from a table, by difficulty. Default `balanced`: easy and moderate parts on Sonnet, hard and frontier parts and the planner, plan critic, completeness, strategist, synthesizer and referee on Opus; one seat of a moderate review panel on Opus; the reflector and the data fetcher on Sonnet. The effort table is unchanged. Before v5 every agent inherited the session's model. Profiles `session` (the old behaviour), `economy`, `mixed`. The attacking side is raised in code to the solver's model and effort when a table puts it lower; a model with no rank never attacks. The cost estimate weighs agents by model.
- Other providers (scripts/crucible_agent.py, engine `call`): one adapter runs an agent on Claude Code headless, the Codex CLI (written from its docs; not run, the CLI is not installed) or any OpenRouter model (own tool loop: read, write, sandboxed shell; schema check with two correction turns; no-training provider policy). Inside a run a non-Claude route sits behind a Haiku relay agent; the adapter reads the prompt from the relay's own transcript, and the engine accepts the result only when its checksum matches, else the Claude route answers. Verified live once outside a run: a 6 KB result relayed unchanged. Optional second attacker from another family on a first submission (`critic2`, profile `mixed`).
- "None" is not a finding: attackers on every model except Sonnet at low effort wrote "none found" in integrity_violation, which the engine read as a violation and sent clean work back (found in calibration: every refusal of a clean submission, across 11 models, was this; in 142 real attacks on Opus it happened once). The attacker now returns a boolean integrity_ok; none-like text in list fields (material flaws, untried avenues, remaining flaws, disputes) is dropped; a contract's frozen_dir must be a path.
- Efficiency log (scripts/crucible_run.py build_efficiency, `efficiency`): every save writes efficiency.json (active and stalled time, agents alive at once, share of time with one or two alive, per-part span, chain and idle time, output spent after first rounds, first-round acceptance per model, time and tokens per role and model) and a summary in the registry; the reflector reads it (new finding category `speed`), and the periodic review's history pack carries it.
- Products (`--improve`, `crucible_run.py rsi|rsi-init`, references/RSI-template.md): a product repo keeps its improvement policy in RSI.md and one file per feedback item; a feedback item is done only after a check that failed because of it passes, with the regression suite.
- Calibration (calibration/, `--calibrate`): 12 probes with known answers (9 review, 3 solving) run through the same adapter. Result of 2026-11-15 (calibration/results/20261115.json): every model caught every planted flaw and solved every solving probe, so the probes are a floor, not a ranking. Two things did separate: GPT-6.1 Terra refused a correct submission at both efforts with invented blocking findings (not used as an attacker), and Sonnet at low effort once ran no executed check. Sonnet at medium was the fastest setting that got everything right (12 s a review probe; Opus high 34 s; Haiku high 52 s).
- Resume: prompts no longer depend on which part happened to finish first (the atlas shown to a part is fixed when it starts and rendered in id order; results are listed in plan order), because the runtime replays an agent only when its prompt is unchanged.
- PROTECTED.md 4, 11 and 14 reworded to match (the invariants hold; their mechanisms changed). tests/run.mjs: the expectations that encoded escalation and the three-round saturation rule were replaced by the new behaviour, on the user's delegation; 30 tests added; each new mechanism's test fails with the mechanism removed.
- Not verified on a real run yet: everything above ran only in the mock harness, the calibration and one live relay. The first real run is the test; compare its efficiency.json with the numbers above.
- Left out on purpose: time-based hedging of slow parts (the runtime gives scripts no clock), System One classifiers such as Jev as gates (a script cannot call them without an agent), switching to OpenRouter when the subscription limit is hit (the relay itself needs a Claude agent; this needs a runner outside Claude Code).

## 2026-11-13 (manual; decisions delegated by the user): v4.3, fixes from the continued self-audit
Evidence: the continuation of runs/20261112-120719-crucible-self-audit-before-real-use (36 agents, wrapped at its 5% ceiling); each item was reproduced there by a scenario on pristine v4.2 and has a regression test here that fails when the fix is reverted.
- Termination (8 patches, 47 lines, from scopes/termination-v42/round-03/artifacts/patches): a fatal objection dropped for missing evidence, or confirmed open by the solver, no longer lets a result survive; an escalation that does worse keeps the first attempt; the ceiling always leaves room for one escalation of the costliest easy/moderate scope (trivial runs keep their small ceiling); parallel parts hold their reserved agents so they cannot overshoot the ceiling (up to 36% before); a single-part run that wraps writes a handoff; "nothing left to try" is not accepted while untried avenues are listed; the round cap always covers patience + 1 (quick depth could never judge a moderate part stuck); solvers are no longer told about an exhaustion claim they never made.
- Decisions taken (the user delegated them, preferring accuracy and autonomy): an escalation that would pass the ceiling is skipped alone and the rest of the run goes on (it used to wrap the whole run, leaving later parts unreviewed); escalation room is counted inside the ceiling shown at approval; the open-fatal trade-off is accepted (an unsupported fatal blocks survival, but the stall rule still ends the part, honestly unverified); the appeal stays exempt from the ceiling like synthesis (one agent that protects a correct result from a wrong refutation).
- Also fixed: an escalated attempt starts fresh (it inherited the resumed round, prior state and contract path); the no-claim fallback points at the last round actually run (it was off by the resume offset); a result is never verified when most of its reviewers failed (one vote of three could verify it).
- Outputs: the harness refuses subagent writes of report.md / answer.md / crucible-handoff.md ("subagents should return findings as text"; it hit the closer and the synthesizer in both live sessions, so the front desk got the previous session's answer). - treg: `/treg` survives stop and continue (the front desk lists it in problem.md's flags; `continue-info` reports `treg`, reading only flag lines, so a problem that merely mentions /treg does not turn it on, and --no-evolve no longer cancels it); a `tregBudget` arg reaches every agent (a budget in the problem text reached 0/42 work prompts); `save` prints the run's own treg cost from metrics (the ledger line counted the whole session). Cache hook: spelling variants of one call share a key (0.1/0.10, get/GET, params/query); a claimant slower than the wait no longer makes every waiter pay (wait 240 s, stale after 300 s, waiters are told to resend); a failed or refused call by another agent never wipes a running claim; stale-claim takeover is atomic; PermissionDenied registered to clear a refused call's claim; PreToolUse timeout 300 s. Left out on evidence: the proposed live-endpoint pattern additions (fixed 1 of 6 misses out of sample).
- Docs: unattended runs need auto mode (or allow rules), noted in SKILL.md.

## 2026-11-12 (manual, with the user): v4.2, fixes from the self-audit's findings
Evidence: the closed self-audit (runs/20261112-120719-crucible-self-audit-before-real-use, answer.md and checkpoint.json); each item below was reproduced there.
- Checks: a critic check has a kind (ran / computed / source_confirmed / inspected); reading the submission no longer counts as executed, so nothing is verified on inspection alone.
- Frozen-contract fingerprint: the command was unquoted and hashed nothing on paths with spaces (14/14 contracts); now quoted and null-separated, with a file count, and an empty-input hash is never trusted.
- Plan review: a failed plan critic was logged as approved, and a final revision was never re-reviewed silently; `plan.review_status` now says which, and the front desk tells the user in plain words.
- Robustness: a throwing agent (structured-output failures, stalls, hard budget stop) used to crash the whole run; it now becomes a missing result, is listed in `failedAgents`, and the synthesizer caveats what depended on it.
- Context: every agent is pointed at problem.md (the user's words and context reached only the planner); synthesizers see the success definition; reviewers of escalated or resumed scopes get the contract that was actually used; the review panel always includes independent reproduction (planner lenses crowded it out); only coupling that blocks correctness triggers restructuring (15/15 scopes triggered it); a shared fetch counts only if it wrote files.
