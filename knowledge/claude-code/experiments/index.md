# experiments

* [Agents of a run keep their cache five minutes; a longer command makes them pay for their context again](agent-cache-lifetime.md) - In the first large run 57% of all cache writes were rebuilds after a command of 5 to 30 minutes. The one-hour lifetime is switched on by one variable or per agent type. **[high]**
* [Code Mode did not reduce model calls or tokens on five small tasks](code-mode-model-calls-on-small-tasks.md) - The same five tool-heavy tasks, all solved correctly both ways: 15 model calls and 322K tokens read without Code Mode, 17 and 301K with it. **[high]**
* [Code Mode reaches the agents of a workflow, in a terminal session only](code-mode-reaches-workflow-agents.md) - In a terminal session with Code Mode on, a workflow agent has only the script tool and the result tool directly; in an SDK app it has the ordinary tools. **[high]**
* [No agent of the first large run compacted; capping context earlier would save little](context-growth-without-compaction.md) - Agents grew to 677K tokens at most and never compacted. Only 4% of all cache reads happened above a context of 400K, so an earlier cap is not worth what compaction loses. **[high]**
* [Custom agent types work in a workflow, and crucible does not use them](custom-agent-types-in-workflows.md) - A workflow agent can run as a custom agent type: its tool list and cache lifetime apply. The type must exist when the session starts. Nothing it gives crucible is worth an install step. **[high]**
* [One launch flag takes the messaging tools away from every agent of a run](deny-messaging-tools-for-a-run.md) - Started with --disallowedTools SendMessage,ListAgents, a session's workflow agents cannot list or message other agents. Crucible does not set it by default. **[high]**
* [A command of eleven minutes finishes inside a Code Mode agent of a workflow](long-command-in-code-mode.md) - A script that waits is stopped after ten minutes, but a long shell command moved to the background by itself and the agent collected its output: one attempt, no loss. **[high]**
* [An agent of a workflow can nest by starting a child session from the shell](nesting-through-a-child-session.md) - A workflow agent has no Agent tool, but it can run a headless claude from Bash, and that child nests its own subagents: three levels ran under one agent of a run. **[high]**
* [An agent of a workflow has no helper tool of its own](workflow-agents-cannot-start-helpers.md) - Tested four ways on two surfaces: no agent started by a workflow script gets the Agent tool. Nesting is possible only through a child session started from the shell. **[high]**
* [The cap on agents working at once holds a run back, and the setting lifts it](workflow-concurrency-cap.md) - Twelve agents started together: six worked at once with the default on an 8-core machine, twelve with the variable set to 12. The first large run sat at six for 78% of its time. **[high]**
