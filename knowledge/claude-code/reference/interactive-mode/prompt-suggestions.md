# What it is

On first open, an example prompt drawn from git history appears; after replies Claude Code can suggest the next prompt. `Tab` or `Right arrow` places it, `Enter` submits. Each suggestion is a short background request to the session model, counted against plan limits or API cost, mostly cache reads.

# How to use it

- Disable: toggle **Prompt suggestions** in `/config`; set `promptSuggestionEnabled` to `false`; or set `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false` (takes precedence over the setting).
- Organization-wide: set `promptSuggestionEnabled` false in managed settings and also set `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION` to `false` under the managed `env` key.
- Setting the variable to `true` keeps suggestions on near the usage limit (before v2.1.238 they were skipped anyway) and restores normal frequency after the notice `Showing fewer prompt suggestions · use one to bring them back`.
- Print mode: not generated by default. Pass `--prompt-suggestions` with `-p "<prompt>" --output-format stream-json --verbose` to get a `prompt_suggestion` message after each turn that produces one.

# Limits and defaults

Off by default, and the toggle hidden, in sessions that do not fetch feature flags (third-party provider, Claude apps gateway) and in a first session after install or upgrade. Skipped when: prompt cache is cold, after the first turn in some sessions, previous response errored, in plan mode, near/at usage limit, and in agent team teammate sessions by default (the lead shows them). Very short conversations and cold caches can yield none in `-p`.
