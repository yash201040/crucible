# What it is

Start with `/status` to see which files loaded; `claude doctor` covers wider checks.

# How to use it

A value you set is ignored because:
- A higher level (another file, `--settings`, managed) sets it, or a flag or env var overrides the key (decided per key in the settings reference).
- A security key keeps its strict value (e.g. project `true` for `disableClaudeAiConnectors`); see [exceptions](./managed-precedence-exceptions.md).
- The file cannot set that value: `permissions.defaultMode` values `auto` and `bypassPermissions` do not take effect from project or local settings (use user or managed settings, or `--permission-mode` per session); before v2.1.257 `bypassPermissions` worked from any file. Telemetry export variables in an `env` block are also ignored from project or local settings except a few off values.
- The file is broken (see [fix a broken file](./check-and-fix-settings.md)).

A change made inside Claude Code (e.g. `/model` default) is lost in new sessions if `~/.claude/settings.json` is not writable (generated by another tool or a read-only link): it applies to the current session only. Also check whether the change was one-session or a higher level sets the key.

A managed change has not reached you: managed sources arrive on a per-source schedule, so restart first; if `/status` names a different source, a higher-priority source applies.

# Limits and defaults

A committed `.claude/settings.json` key does not reach teammates when: (1) the key's scope is `User, local, or managed`, `User or managed`, `User`, `Managed` or `Global config` in the settings index (never applies from the shared file, apart from a few that a repo file can switch off; `Global config` keys apply only from `~/.claude.json`); or (2) the key waits for trust: `permissions.allow` rules, `permissions.additionalDirectories`, `extraKnownMarketplaces` and most `env` values apply only after each teammate trusts the folder. `deny` and `ask` rules apply immediately.

Permission rule surprises: "Yes, and don't ask again" saves an `allow` to the local file, which does not outrank an `ask` rule from a project or managed file. In the VS Code extension the approval card can pick the destination file (including shared); in the CLI only the local file. Org allow rules still merge with yours unless `allowManagedPermissionRulesOnly`.
